# 分享前检查清单

不要只删除 `raw/` 就认为已经脱敏。`wiki/`、`outputs/`、索引、日志、图片、Git 历史和编辑器状态里都可能残留私人信息。

## 必查

- [ ] `raw/` 中只有占位文件，没有原文、录音、截图、PDF、聊天记录或转写稿。
- [ ] `wiki/` 中只有准备公开的通用知识，没有个人经历、客户、同事、课程、商业判断或长期记忆。
- [ ] `outputs/` 中没有文章草稿、报告、翻译、合同、演讲稿或交付材料。
- [ ] `assets/` 中没有照片、截图、二维码、证件、票据或带水印文件。
- [ ] `wiki/log.md`、索引和 README 没有暴露文件名、主题名、来源名或历史路径。
- [ ] 不含 `.env`、令牌、Cookie、SSH 配置、密码、私钥、服务器地址或账号信息。
- [ ] 不含用户主目录绝对路径、邮箱、手机号、身份证号或内部平台 ID。
- [ ] `.obsidian/workspace.json`、会话文件、缓存、临时目录和 `.DS_Store` 已排除。
- [ ] 已运行 `bash scripts/privacy_scan.sh`，并人工复核所有提示。
- [ ] 如果目录曾提交过私人内容，分享的是全新的干净副本，而不是带旧 Git 历史的仓库。

## 建议流程

1. 从这个空白模板重新复制一份。
2. 只把确认可公开的规则、脚本和 Skills 放进去。
3. 运行隐私扫描。
4. 人工打开最终压缩包再检查一次文件清单。
5. 最后才上传或发送。
